# 1. Core Concepts

## What Are Logs?

Logs are records of events generated by a system or application.

```text
Application
     ↓
   Logs
     ↓
Troubleshooting
```

### Why Logs Matter

Logs are used for:

* Debugging application failures
* Monitoring system health
* Security auditing
* Performance analysis
* Compliance requirements
* Investigating incidents

---

## Types of Logs

| Type                     | Location        | Examples                         |
| ------------------------ | --------------- | -------------------------------- |
| **System Logs**          | `/var/log/`     | `syslog`, `messages`, `kern.log` |
| **Application Logs**     | `/var/log/app/` | Nginx, MySQL, Docker             |
| **Authentication Logs**  | `/var/log/`     | `auth.log`, `secure`             |
| **Boot Logs**            | `/var/log/`     | `boot.log`, `dmesg`              |
| **Kernel Logs**          | `/var/log/`     | `kern.log`, `dmesg`              |
| **Package Manager Logs** | `/var/log/`     | APT history, `yum.log`           |

---

## Log Levels — Syslog Severity

| Level         | Value | Meaning                   | Example                    |
| ------------- | ----: | ------------------------- | -------------------------- |
| **Emergency** |     0 | System is unusable        | Kernel panic               |
| **Alert**     |     1 | Immediate action required | Disk full                  |
| **Critical**  |     2 | Critical condition        | Service crashed            |
| **Error**     |     3 | Error condition           | Database connection failed |
| **Warning**   |     4 | Warning condition         | High CPU                   |
| **Notice**    |     5 | Normal but significant    | Service started            |
| **Info**      |     6 | Informational             | User logged in             |
| **Debug**     |     7 | Debug information         | Detailed debugging         |

### Interview Answer

> I use appropriate log levels depending on the environment. Production systems generally use INFO or WARNING for normal operational visibility, while DEBUG is primarily useful during development or detailed troubleshooting. ERROR and CRITICAL events require attention.

# 3. Essential Commands

## Viewing Logs

### View Entire File


```bash
less /var/log/syslog
```


### Last Lines

```bash

```

### Follow Logs in Real Time

```bash
tail -f /var/log/syslog
```

### Follow Last 50 Lines

```bash
tail -n 50 -f /var/log/syslog
```

---

## Searching Logs

### Search for Errors

```bash
grep "error" /var/log/syslog
```

### Case-Insensitive Search

```bash
grep -i "error" /var/log/syslog
```

### Show Context

```bash
grep -C 5 "error" /var/log/syslog
```

Shows 5 lines before and after each match.

### Recursive Search

```bash
grep -r "error" /var/log/
```

### Search Multiple Files

```bash
grep "error" /var/log/*.log
```

### Show Line Numbers

```bash
grep -n "error" /var/log/syslog
```

### Count Matches

```bash
grep -c "error" /var/log/syslog
```

### Regular Expression

```bash
grep -E "error|failed" /var/log/syslog
```

---

## Filtering and Processing

### Follow Only Errors

```bash
tail -f /var/log/syslog | grep -i error
```

### Search Specific Time

```bash
grep "Aug 18 10:" /var/log/syslog
```

### Find Errors and Failures

```bash
grep -i "error\|fail\|crit" /var/log/syslog
```

### Exclude a Pattern

```bash
grep -v "healthy" /var/log/syslog
```

### Find Unique Errors

```bash
grep "error" /var/log/syslog | sort | uniq -c
```

### Find Logs for a Process

```bash
grep "nginx" /var/log/syslog
```

---

## Log Statistics

### Count Errors

```bash
grep -c "ERROR" app.log
grep -c "WARN" app.log
```

### Count Unique Errors

```bash
grep "ERROR" app.log | sort | uniq -c | sort -nr
```

### Count Logs by Hour

```bash
grep "Aug 18" /var/log/syslog | cut -d: -f1 | sort | uniq -c
```

### Show Most Frequent Errors

```bash
grep -o "ERROR.*" app.log |
cut -d' ' -f1-5 |
sort |
uniq -c |
sort -nr |
head -10
```

---

## Log Management

### Compress Logs

```bash
gzip /var/log/syslog.1
```

### Read Compressed Logs

```bash
zcat /var/log/syslog.1.gz
```

### Search Compressed Logs

```bash
zgrep error /var/log/syslog.1.gz
```

### Archive Logs

```bash
tar -czf logs-$(date +%Y%m%d).tar.gz /var/log/*.log
```

### Delete Old Logs

```bash
find /var/log -name "*.log" -mtime +30 -delete
```

> Use deletion commands carefully in production. Verify the files and retention requirements before removing logs.

# 4. Journald — systemd Logs

## What is Journald?

`journald` is systemd's logging system and is a modern Linux logging mechanism.

```text
Application
     ↓
 journald
     ↓
journalctl
```

### Why Use Journald?

* Structured logging
* Rich metadata
* PID information
* User information
* Service information
* Indexed searching
* Automatic log rotation
* Centralized journal storage

---

### View All Logs

```bash

```

### Service Logs

```bash

```

### Current Boot


```bash

```

### Follow Logs

```bash
journalctl -f
```


## Reduce Journal Size

Limit by size:

```bash

```

Limit by time:

```bash

```

---

## Verify Journal Integrity

```bash

```

---

## Journald Configuration

Configuration file:

```text
/etc/systemd/journald.conf
```

Example:

```ini
[Journal]
Storage=persistent
Compress=yes
SystemMaxUse=1G
SystemMaxFileSize=100M
MaxRetentionSec=1month
ForwardToSyslog=yes
```

After changing configuration:

```bash
sudo systemctl restart systemd-journald
```

---

## Journald vs Traditional Logs

| Feature     | Journald           | Traditional Log Files |
| ----------- | ------------------ | --------------------- |
| Format      | Structured         | Plain text            |
| Metadata    | Rich               | Limited               |
| Search      | Indexed            | Usually grep          |
| Rotation    | Automatic          | Usually logrotate     |
| Storage     | Binary journal     | Plain text            |
| Portability | Harder to transfer | Easy to transfer      |

# 5. Log Rotation

## What is Log Rotation?

Log files can grow indefinitely and eventually consume disk space.

**Log rotation** automatically:

* Renames old logs
* Creates new log files
* Compresses old logs
* Removes logs beyond retention
* Prevents disk exhaustion

Example:

```text
app.log
   ↓
app.log.1
   ↓
app.log.2
   ↓
app.log.3
   ↓
app.log.4
   ↓
Oldest logs removed
```

### Rotation Triggers

Log rotation can happen based on:

* File size
* Time
* Both size and time

Example:

```text
100 MB
```

or:

```text
Daily
```

---

## `logrotate`

`logrotate` is the standard Linux utility for rotating, compressing, and removing old logs.

### Configuration

Global configuration:

```text
/etc/logrotate.conf
```

Service-specific configuration:

```text
/etc/logrotate.d/
```

---

## Example Nginx Configuration

```text
/var/log/nginx/*.log {
    daily
    rotate 7
    missingok
    compress
    delaycompress
    notifempty
    create 640 nginx nginx

    postrotate
        systemctl reload nginx
    endscript
}
```

### Meaning

| Option          | Purpose                                   |
| --------------- | ----------------------------------------- |
| `daily`         | Rotate daily                              |
| `weekly`        | Rotate weekly                             |
| `monthly`       | Rotate monthly                            |
| `size 100M`     | Rotate when file exceeds 100 MB           |
| `rotate 7`      | Keep 7 old logs                           |
| `compress`      | Compress rotated logs                     |
| `delaycompress` | Delay compression by one rotation         |
| `missingok`     | Ignore missing log files                  |
| `notifempty`    | Don't rotate empty files                  |
| `create`        | Create new log with specified permissions |
| `postrotate`    | Execute commands after rotation           |
| `prerotate`     | Execute commands before rotation          |

---

## Logrotate Commands

### Test Configuration

```bash
logrotate -d /etc/logrotate.conf
```

### Force Rotation

```bash
sudo logrotate -f /etc/logrotate.conf
```

### Verbose Mode

```bash
sudo logrotate -v /etc/logrotate.conf
```

# 6. Troubleshooting Scenarios

## Scenario 1 — Application Failing

### Problem

An application crashes and you need to determine why.

### Troubleshooting Flow

```bash
# 1. Check service status
sudo systemctl status myapp

# 2. Check service logs
sudo journalctl -u myapp -n 50
sudo journalctl -u myapp -f

# 3. Check application logs
tail -f /var/log/myapp/app.log

# 4. Check system logs
tail -f /var/log/syslog | grep -i myapp

# 5. Search for errors
grep -i "error\|fail\|crash" /var/log/myapp/*.log
```

---

## Scenario 2 — Server Unresponsive

### Problem

The server is slow or unresponsive.

### Troubleshooting Flow

```bash
# Check system health
uptime
top
free -h

# Check system errors
tail -100 /var/log/syslog
journalctl -p err -n 50

# Check kernel logs
dmesg | tail -50
journalctl -k -n 50

# Check for OOM
dmesg | grep -i oom
journalctl | grep -i oom

# Check disk space
df -h
df -i

# Check failed services
sudo systemctl --failed
```

### Key Things to Check

```text
CPU
RAM
Disk Space
Inodes
Kernel Errors
OOM Killer
Failed Services
```

---

## Scenario 3 — Application Throwing Errors

### Identify Error Pattern

```bash
grep -i "error" /var/log/app/app.log | tail -20
```

### Count Errors

```bash
grep -c "error" /var/log/app/app.log
```

### Group Errors by Type

```bash
grep "error" /var/log/app/app.log |
cut -d' ' -f4- |
sort |
uniq -c |
sort -nr
```

### Check a Specific Time

```bash
grep "Aug 18 10:" /var/log/app/app.log | grep -i error
```

### Correlate With System Events

```bash
grep "Aug 18 10:" /var/log/syslog
```

---

## Scenario 4 — Logs Growing Too Fast

### Problem

Logs are consuming disk space rapidly.

### Step 1 — Check Disk

```bash
df -h
```

### Step 2 — Find Large Logs

```bash
find /var/log -type f -size +100M -exec ls -lh {} \; 2>/dev/null
```

### Step 3 — Check Log Directory Usage

```bash
ls -lh /var/log/*.log
du -sh /var/log/*
```

### Step 4 — Investigate Specific Logs

```bash
tail -100 /var/log/nginx/access.log
tail -100 /var/log/app/app.log
```

Look for:

* Excessive requests
* Repeated application errors
* Unexpected traffic
* Debug logging accidentally enabled

### Step 5 — Check Rotation

```bash
cat /etc/logrotate.d/app
```

### Step 6 — Rotate / Reduce Logs

```bash
sudo logrotate -f /etc/logrotate.conf
```

For journald:

```bash
sudo journalctl --vacuum-size=1G
```

---

## Scenario 5 — Permission Denied on Logs

### Error

```text
Permission denied: /var/log/app/app.log
```

### Diagnosis

```bash
# Check file permissions
ls -l /var/log/app/app.log

# Check directory permissions
ls -ld /var/log/app

# Check application user
ps aux | grep app
```

### Fix

```bash
sudo chown appuser:appgroup /var/log/app/app.log
sudo chmod 644 /var/log/app/app.log
```

---

## Scenario 6 — Logs Not Being Written

### Diagnosis

```bash
# Check directory
ls -ld /var/log/app

# Test write permissions
sudo -u appuser touch /var/log/app/test.log

# Check application process
ps aux | grep app

# Check open log files
lsof -p PID | grep log

# Check application logging configuration
cat /etc/app/config.yaml | grep log

# Check logrotate configuration
sudo logrotate -d /etc/logrotate.conf
```

### Things to Verify

* Application is running
* Log directory exists
* Application has write permission
* Log path is correct
* Log level is appropriate
* Log rotation is not interfering

# 7. Interview Questions & Answers

## Q1. Where are logs typically stored on Linux?

> System logs are commonly stored under `/var/log/`. Application logs may be stored under `/var/log/app/` or another application-specific location.

---

## Q2. How do you view logs in real time?

```bash
tail -f /var/log/syslog
```

Or:

```bash
journalctl -f
```

For a specific service:

```bash
journalctl -u nginx -f
```

---

## Q3. Difference Between `tail -f` and `journalctl -f`?

> `tail -f` follows a traditional log file. `journalctl -f` follows systemd journal logs and provides access to structured journal metadata.

---

## Q4. How do you search for errors in logs?

```bash
grep -i "error" /var/log/syslog
```

```bash
journalctl -p err
```

Or recursively:

```bash
grep -r "error" /var/log/
```

---

## Q5. What is Log Rotation and Why Is It Important?

> Log rotation prevents log files from consuming all available disk space. It automatically rotates, compresses, and removes old logs according to configured retention policies.

---

## Q6. How Do You Configure Log Rotation?

> Log rotation is configured through `/etc/logrotate.conf` and service-specific files under `/etc/logrotate.d/`.

For example:

```text
/etc/logrotate.d/nginx
```

---

## Q7. How Do You Check Log Disk Usage?

```bash
du -sh /var/log
```

For journald:

```bash
journalctl --disk-usage
```

---

## Q8. Difference Between Syslog and Journald?

> Syslog traditionally uses plain-text log files, while journald is systemd's modern logging system and provides structured information and richer metadata.

---

## Q9. How Do You Reduce Log Disk Usage?

```bash
journalctl --vacuum-size=500M
```

For traditional logs:

```bash
find /var/log -name "*.log" -mtime +30 -delete
```

And adjust `logrotate` retention policies when appropriate.

---

## Q10. How Do You Follow Only Errors?

```bash
tail -f /var/log/syslog | grep -i "error"
```

Or:

```bash
journalctl -f -p err
```

---

## Q11. How Do You Troubleshoot an Application That Isn't Logging?

> First verify that the application is running. Then check that the log directory exists, confirm the application has write permissions, verify the configured log path and log level, and finally check whether log rotation is affecting the file.

---

Check for OOM events:

```bash
dmesg | grep -i oom
```

Or:

```bash
journalctl | grep -i oom
```

```text
1. Is the application running?
   → ps aux | grep app

2. Does the log directory exist?
   → ls -ld /var/log/app

3. Does the application user have write permission?
   → sudo -u appuser touch /var/log/app/test.log

4. Is the configured log level correct?
   → Check application configuration

5. Is the configured log path correct?
   → Check application configuration

6. Is log rotation interfering?
   → sudo logrotate -d /etc/logrotate.conf
```

---

## Disk Full Because of Logs

```text
1. Check disk usage
   → df -h

2. Find large logs
   → find /var/log -type f -size +100M

3. Reduce journald
   → journalctl --vacuum-size=500M

4. Rotate logs
   → sudo logrotate -f /etc/logrotate.conf

5. Remove old logs according to retention policy
   → find /var/log -name "*.log" -mtime +30 -delete
```

# 10. Common Interview Traps

## Trap 1 — Forgetting Journald

❌ **Bad Answer:**

> I only use `tail -f /var/log/syslog`.

✅ **Good Answer:**

> I use both traditional log files and journald. For systemd-managed services, I use `journalctl`.

---

## Trap 2 — Not Knowing Log Rotation

❌ **Bad Answer:**

> I manually delete old logs.

✅ **Good Answer:**

> I use logrotate to automatically rotate, compress, and remove logs according to a retention policy.

---

## Trap 3 — Ignoring Permissions

❌ **Bad Answer:**

> I always use sudo to access application logs.

✅ **Good Answer:**

> I check file and directory permissions and ensure the application user has the required access to write its logs.

---

## Trap 4 — Using `cat` for Large Files

❌ **Bad Answer:**

```bash
cat /var/log/syslog
```

for every troubleshooting task.

✅ **Good Answer:**

> I use `less`, `tail`, `grep`, or `journalctl` for large logs so I can efficiently inspect only the relevant data.

### Must-Know Commands

```bash
# Traditional logs
tail -f /var/log/syslog
less /var/log/syslog
grep -i "error" /var/log/syslog
grep -C 5 "error" /var/log/syslog

# Journald
journalctl
journalctl -u nginx
journalctl -f
journalctl -u nginx -f
journalctl -p err
journalctl -b
journalctl --since "1 hour ago"

# Journal disk management
journalctl --disk-usage
journalctl --vacuum-size=500M

# Log rotation
logrotate -d /etc/logrotate.conf
sudo logrotate -f /etc/logrotate.conf

# Disk troubleshooting
df -h
df -i
du -sh /var/log

# Kernel / OOM
dmesg
dmesg | grep -i oom
journalctl -k

# Compressed logs
zcat /var/log/syslog.1.gz
zgrep error /var/log/*.gz
```
